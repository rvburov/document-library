# Установка, удаление и обновление

## Назначение

Программа ставится без прав администратора и обновляется из общей папки в сети, как SmartBase:
у пользователей нет прав на установку программ, а служба ИТ отвечает долго. Отдельного
установщика нет — тот же файл программы под именем с окончанием `-Setup` работает установщиком.

## Как работает

### Режим запуска

`ResolveMode` смотрит на аргументы и имя файла:

- `--uninstall` — удаление;
- имя файла (Windows, Linux) или бандла (macOS) оканчивается на `-Setup` — установка;
- иначе — программа.

Поэтому установщик нельзя переименовывать: `PdfLibrary-Setup (1).exe`, который создает браузер
при повторном скачивании, запустится как программа.

### Куда ставится

| ОС | Программа | Данные (не удаляются вместе с программой по умолчанию) |
|---|---|---|
| Windows | `%LOCALAPPDATA%\Programs\PdfLibrary\PdfLibrary.exe` | `%LOCALAPPDATA%\PdfLibrary` |
| Linux | `~/.local/opt/PdfLibrary/PdfLibrary` | `~/.local/share/PdfLibrary` |
| macOS | `~/Applications/PdfLibrary.app` | `~/Library/Application Support/PdfLibrary` |

Папка установки намеренно не совпадает с папкой данных: удаление чистит папку установки, а
источники, группы и метки человека лежат в `library.db`. Выбранную в окне папку установщик
приводит к «выделенной» — дописывает `PdfLibrary`, если ее там нет, чтобы удаление не задело
чужие файлы общей папки. Удаляются только свои файлы, папка — только если опустела.

Рядом с программой кладется установщик (`PdfLibrary-Setup[.exe|.app]`): он — единственная точка
входа для переустановки и удаления. Ярлыки: Windows — меню «Пуск» и, по галочке, рабочий стол;
Linux — `.desktop` в меню приложений и на рабочем столе; macOS — регистрация в Launchpad
(`lsregister`) и снятие карантина с установленного бандла. Список папок установки — в
`installs.json` в папке данных: по нему окно установщика пишет «Обновить» или «Переустановить», а
автозапуск отличает установленную копию от портативной.

### Обновление из папки

В «Настройки → О программе» задается **папка обновлений** — обычно общая папка в сети, куда
кладут новую сборку (`PdfLibrary-Setup` или `PdfLibrary` нужной ОС в корне папки).

- **«Проверить»** сравнивает файл в папке со своей версией: на Windows — по версии из ресурса
  `.exe`, на Linux и macOS (версии в файле нет) — по размеру и времени правки с допуском 2 с.
  Так раздаются и сборки без смены номера.
- **Обновить** — файл копируется во временную папку и запускается с `--apply-update --pid
  <процесс> --target <файл программы>`; копия ждет выхода программы, заменяет файл собой,
  обновляет лежащий рядом установщик (только если он там уже был) и запускает программу заново.
- **«Автообновление»** — при запуске программа сама проверяет папку и ставит новую версию без
  вопросов. Папка недоступна (сервер выключен) — тихо, след в журнале. Обновляется только
  установленная копия: запуск из папки сборки обновлять нечем.

### Удаление

`PdfLibrary-Setup --uninstall` или пункт «Удалить» в окне установщика: ярлыки, запись в
«Приложениях», автозапуск, папка установки. Папка данных — только по галочке. На Windows
запущенный файл удалить нельзя, поэтому папку дочищает отложенный `.bat` после выхода.

## Взаимодействия

- **Автозапуск** ([Utils/Autostart.cs](../../../Utils/Autostart.cs)) указывает на установленный
  файл; удаление снимает его первым.
- **Выпуск на GitHub** ([release.md](release.md)) раздает установщики; чтобы обновить
  пользователей, установщик из релиза кладут в папку обновлений.
- **Журнал** — каждый шаг проверки и обновления пишется в `logs.db` («Настройки → Диагностика»).

## Проверено и не проверено

Тесты `Tests/Unit/InstallServiceTests.cs` и `AutostartTests.cs` покрывают чистую логику: какие
файлы свои, выделенная папка, разбор записей автозапуска, обновление установщика рядом. Сборки
под три ОС и запуск собранной программы под Linux проверены в облачной среде. Настоящая установка,
ярлыки, «Приложения» Windows, Launchpad и обновление из сетевой папки — только на машине
пользователя: чек-лист — [manual-check.md](../qa-checklists/manual-check.md).
