# Полная проверка на GitHub

Сборка, все тесты и стенд экранов на четырех операционных системах по одной команде. Сама не
запускается — только когда попросили. Ничего не публикует и не собирает в установщики. Модуль
перенесен из SmartBase без PostgreSQL, расширений и закрытого контура — их у программы нет.

## Где в коде

| Файл | Роль |
|---|---|
| [.github/workflows/build.yml](../../../.github/workflows/build.yml) | сам прогон: два job'а, пять раннеров |
| [Scripts/ci/setup-remote.sh](../../../Scripts/ci/setup-remote.sh) | заводит команду `git push actions`, один раз |
| [Scripts/ci/ci-test.sh](../../../Scripts/ci/ci-test.sh) | тесты модуля |
| `docs/developer/guides/ci.md` | этот файл |

## Настройка — один раз на машине

```bash
Scripts/ci/setup-remote.sh
```

Без нее `git push actions` отвечает `'actions' does not appear to be a git repository`.

## Запуск

```bash
git push actions
```

Отправляет `master` и перематывает служебную ветку `ci` на тот же коммит; ее push и запускает
прогон. Дальше — вкладка **Actions** → запуск **Build**.

- набирать из корня репозитория; отправляется всегда `master`, с какой бы ветки ни набрали;
- `git push` без `actions` не запускает ничего;
- код не менялся → ветка `ci` не сдвинется и прогон не начнется; перезапуск — кнопкой
  **Run workflow** на вкладке Actions.

## Какие проверки идут

На каждом из четырех раннеров — Linux, Windows, macOS Apple Silicon, macOS Intel:

1. **Сборка** `dotnet build PdfLibrary.csproj -c Release` — оба таргета, `net10.0` и
   `net10.0-windows10.0.17763` ([build-and-run.md](build-and-run.md)).
2. **Модульные тесты** `dotnet test Tests/Unit`.
3. **Интеграционные тесты** `dotnet test Tests/Integration` — настоящая SQLite, настоящие PDF и
   PDFium каждой платформы: регистр имен, разделители путей, наблюдение за папками.
4. **Стенд экранов** `dotnet run --project Tests/Screens` — живая Avalonia без экрана; кадры
   прикладываются к прогону вложением `screens-<ОС>-<архитектура>`.

Упавшая платформа не отменяет остальные.

Только на Linux:

5. **Связка с D-Bus для уведомлений.** Под `dbus-run-session` гоняется
   `LinuxNotificationsTests`. Ловит разъезд версий `DesktopNotifications.FreeDesktop` и
   `Tmds.DBus`: сборка при нем проходит, а менеджер баннеров падает уже у пользователя, причем
   молча — исключение проглатывается. Отдельный шаг падает, если тест ушел в Skipped.

И последним — **уборка ветки `ci`**: удаляется после прогона, в том числе после красного и
отмененного.

Не проверяется: работа на настоящих файлах пользователя
([manual-check.md](../qa-checklists/manual-check.md)) и упаковка в установщики — это выпуск
([release.md](release.md)).

## Сколько это стоит

Несколько минут по часам — раннеры работают параллельно. Оплачиваемых минут больше: они
считаются по каждому job'у, округляются вверх и умножаются — Linux ×1, Windows ×2, **macOS ×10**.
Публичный репозиторий — бесплатно; приватный — 2000 минут в месяц на бесплатном тарифе. Точная
цифра — **Run details → Usage** на странице прогона.

## Не пересекается с выпуском релиза

- триггеры разные: выпуск — тег `v*`, проверка — ветка `ci`;
- скриптов репозитория не вызывает, только `dotnet`;
- общих файлов нет: удаление любого из модулей не задевает второй.

Перед выпуском прогон обязателен: между выпусками тесты видят одну машину разработчика, а `gate`
релиза идет на Linux. Тест, впервые встретивший другую ОС в момент выпуска, — это красный релиз и
перевыпуск.

## Тесты модуля

```bash
Scripts/ci/ci-test.sh
```

Восемь проверок, чистый bash: YAML разбирается, запуск только по ветке `ci`, скриптов
репозитория workflow не вызывает, проекты и тесты из него существуют, матрица полна, ветка
убирается, модуль отделяем. Нужны, только если правили сам модуль — код проекта они не проверяют.

## Если прогон покраснел

1. **Actions** → красная строка: видно ОС и шаг.
2. Раскрыть шаг — в логе имена упавших тестов; у стенда — строки `FAIL`.
3. Повторить локально той же командой.

## Как удалить модуль

```bash
rm -rf Scripts/ci
rm .github/workflows/build.yml docs/developer/guides/ci.md
git remote remove actions                # на каждой машине, где была настройка
git status --porcelain                   # только строки «D» — ни одного «M»
```

и убрать строку из карты [docs/README.md](../../README.md) — единственное упоминание модуля вне
его файлов (проверка 8 в `ci-test.sh` следит, чтобы других не появилось). Ветку `ci` удалять не
нужно — прогон убирает ее сам.
