# Проверка веток на GitHub

Модульные и интеграционные тесты и стенд экранов на Linux для каждой ветки, отправленной на
GitHub, и каждого PR в `master`. Запускается сам — в отличие от [полной проверки](ci.md), которую
запускают по команде.

## Зачем

Работа уходит на GitHub ветками, а в `master` идет только перемоткой. Тесты гоняются и на своей
машине, но проверка на чистой машине надежнее: на ней нет ни кеша сборки, ни забытых файлов. Этот
прогон дает серверное подтверждение:

- перед отправкой в `master` проверка ветки должна быть зеленой;
- у PR результат виден прямо в PR — сливать красный PR не нужно.

## Где в коде

| Файл | Роль |
|---|---|
| [.github/workflows/branch-tests.yml](../../../.github/workflows/branch-tests.yml) | сам прогон: один job на `ubuntu-latest` |
| `docs/developer/guides/branch-tests.md` | этот файл |

## Когда запускается

| Событие | Запуск |
|---|---|
| push любой ветки, кроме `master` и `ci` | да |
| PR в `master` (открыт или обновлен) | да |
| кнопка **Run workflow** на вкладке Actions | да |
| push `master` | нет — туда приходят уже проверенные коммиты |
| push ветки `ci` | нет — это [полная проверка](ci.md) |
| push тега `v*` | нет — это [выпуск](release.md) |

Push ветки и ее PR — два события на один код: прогон один (группа `concurrency` по имени ветки),
новый push отменяет недоделанный старый.

## Какие проверки идут

1. `dotnet test Tests/Unit --configuration Release`.
2. `dotnet test Tests/Integration --configuration Release` — настоящая SQLite и настоящие PDF,
   сервер не нужен, поэтому набор идет здесь целиком.
3. `dotnet run --project Tests/Screens --configuration Release` — стенд экранов; кадры
   прикладываются к прогону вложением `screens` на неделю.

Культура — `LANG=ru_RU.UTF-8`, как у пользователей: тесты форматирования ждут запятую в числах.

Не входят: другие ОС и связка с D-Bus — это [полная проверка](ci.md).

## Сколько это стоит

Несколько минут на Linux. Публичный репозиторий — бесплатно; для приватного — минуты бесплатного
тарифа (2000 в месяц, множитель Linux ×1).

## Если прогон покраснел

1. **Actions** → **Branch tests** → красная строка → шаг: в логе имена упавших тестов или строки
   `FAIL` стенда.
2. Повторить локально той же командой.
3. Красное в `master` не отправляется — чинится в своей ветке, и ветка отправляется снова.

## Как удалить

```bash
rm .github/workflows/branch-tests.yml docs/developer/guides/branch-tests.md
```

и убрать строку из [docs/README.md](../../README.md). Полная проверка и
выпуск не задеваются: общих файлов и триггеров нет.
